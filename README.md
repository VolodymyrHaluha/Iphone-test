# NEON SPIN — 3D + приватні й групові чати

Безкоштовний статичний PWA-сайт (HTML + CSS + JavaScript) із Firebase Authentication і Cloud Firestore. Працює на Windows, Android, iPhone. Сервер на власному ПК не потрібен.

## Що вже реалізовано

- Неоновий 3D-куб: перетягування мишкою/пальцем, осі X/Y/Z, точні кути, «Скинути до 0°».
- Реєстрація та вхід за **нікнеймом + паролем**.
- Приватні чати один на один і групові чати від 3 до 30 учасників.
- Пошук інших зареєстрованих користувачів за нікнеймом, список своїх чатів, пошук по чатах.
- Синхронізація повідомлень у реальному часі, останні 100 повідомлень у відкритому чаті, збереження історії в Firestore.
- Правила Firestore: читати й надсилати повідомлення дозволено **лише учасникам** відповідного чату.
- Мобільний адаптивний інтерфейс, SVG-іконка, PWA-маніфест, базовий service worker для статичних файлів.

**Що не входить:** передавання файлів, дзвінки, push-сповіщення, індикатор онлайн, редагування складу групи, відновлення пароля, наскрізне (end-to-end) шифрування. Шифрування HTTPS/TLS використовується для передачі даних до Firebase, але це **не E2EE**. Розраховано на невелике коло знайомих, не на публічну платформу.

## 1. Створи Firebase-проєкт

1. Відкрий https://console.firebase.google.com/ і натисни **Add project**.
2. Додай **Web app** (`</>`) і скопіюй об’єкт `firebaseConfig` із **Project settings → General → Your apps → SDK setup and configuration**.
3. Відкрий `firebase-config.js` і заміни всі значення-заглушки своїми (`apiKey`, `authDomain`, `projectId`, `storageBucket`, `messagingSenderId`, `appId`). Firebase web config **не є секретним API-ключем**. **Не вставляй** сюди паролі, service-account private key або admin SDK credentials.

## 2. Налаштуй авторизацію

У Firebase Console → **Authentication → Sign-in method** увімкни **Email/Password** (не Email link). Хоча форма використовує нікнейм, у Firebase Auth цей приклад технічно перетворює його на адресоподібний ідентифікатор: `нікнейм@neonspin.example`.

Це дозволяє працювати **без окремого сервера і справжньої пошти**, але важливо:

- Нікнейми лише `a-z`, цифри, `_`, довжина 3–20. Регістр не має значення.
- Мінімум 8 символів у паролі.
- **Відновити пароль електронною поштою не можна**, тому що ці адреси фіктивні. Якщо людина втратить пароль, потрібен власник Firebase-проєкту та окремий процес адміністративного відновлення акаунта. Для реального публічного продукту краще Firebase Auth зі справжніми email або окремий backend для nickname-login.
- Додавати акаунти може будь-хто, кому доступна сторінка реєстрації. Для **закритого клубу за запрошеннями** потрібні окремі правила допуску / адміністратор, а не лише посилання на сайт.

## 3. Створи Firestore і встав правила безпеки

1. Firebase Console → **Firestore Database → Create database**. Для старту обери регіон, близький до користувачів.
2. Перейди до **Rules**, повністю заміни вміст кодом з `firestore.rules` і натисни **Publish**.
3. **Не** залишай тестові правила `allow read, write: if true`.

Користувач може створити свій профіль `users/{uid}`, подивитися публічні нікнейми інших зареєстрованих людей, створити приватний чат або групу та обмінюватися повідомленнями тільки в тих чатах, де він є учасником. Учасників групи вибирають під час створення; змінювати їх у цій версії не можна.

## 4. Запусти на Windows

Сайт має працювати через HTTP/HTTPS (не `file://`). Найпростіший спосіб, якщо вже встановлено Python:

```bash
cd neon-spin-messenger
python -m http.server 8080
```

Відкрий `http://localhost:8080` в Chrome/Edge. Python **не потрібен для самого сайту** — це лише простий локальний сервер для тестування. Можна використовувати Live Server у VS Code або одразу GitHub Pages.

У **Authentication → Settings → Authorized domains** додай домен хостингу, якщо потрібно. `localhost` для деяких нових проєктів Firebase треба додати вручну. Для онлайн-хостингу використовується HTTPS.

## 5. Безкоштовно розмісти онлайн через GitHub Pages

1. Створи публічний репозиторій, наприклад `neon-spin-messenger`.
2. Завантаж в корінь файли цього архіву (`index.html`, `app.js`, `style.css`, `firebase-config.js`, `firestore.rules`, `manifest.webmanifest`, `sw.js`, каталог `icons`).
3. На GitHub відкрий **Settings → Pages → Build and deployment → Deploy from a branch → main / (root)** і збережи.
4. Отримаєш адресу на кшталт `https://YOUR_USERNAME.github.io/neon-spin-messenger/`.
5. За потреби додай `YOUR_USERNAME.github.io` до Firebase Authentication → **Authorized domains**.
6. Надішли цю адресу другу. Кожен користувач створює власний нікнейм і пароль. Для тесту відкрий сайт у двох браузерах/на двох телефонах під різними акаунтами.

**Пам’ятай:** репозиторій GitHub Pages зазвичай публічний, але приватність повідомлень визначають **Firestore security rules**, а не прихованість коду сайту. Інтернет потрібен для входу, створення чатів та обміну повідомленнями.

## 6. Встановлення на iPhone

1. Відкрий HTTPS-адресу сайту в **Safari**.
2. Натисни **Поділитися → На початковий екран → Додати**.
3. На головному екрані з’явиться іконка NEON SPIN. Jailbreak, App Store і платний Apple Developer Account не потрібні.

## 7. Безкоштовний тариф та витрати

Firebase Spark має квоти; обсяг читань Firestore залежить від числа користувачів, відкритих чатів і повідомлень. Перевір актуальні безкоштовні ліміти й налаштуй сповіщення/моніторинг квот у Firebase Console. GitHub Pages підходить для статичних файлів, але має власні умови використання.

## Схема даних

- `users/{uid}`: `{ uid, nickname, createdAt }`
- `chats/{chatId}`: `{ type, name, memberIds[], createdBy, createdAt, updatedAt, lastText, lastSenderId }`
- `chats/{chatId}/messages/{messageId}`: `{ senderId, text, createdAt }`

**Примітка про захист:** Firebase security rules забороняють неучасникам читати чати, але без серверної перевірки окремих дій можливі зловживання учасниками (наприклад, підміна тексту прев’ю чату в метаданих). Це стартовий застосунок; для публічного запуску додай App Check, антиспам, блокування користувачів, серверну перевірку змін і тестування правил у Firebase Emulator Suite.
